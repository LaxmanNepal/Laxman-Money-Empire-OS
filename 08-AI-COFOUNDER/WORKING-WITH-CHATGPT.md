# Working With ChatGPT as Your AI Cofounder

## What to ask me to do

Instead of: `give me ideas`

Use: `inspect my repository, identify the highest-leverage revenue opportunity, explain the evidence, then implement it.`

## Five modes

### 1. Strategist
Ask for prioritization, business models, positioning and experiments.

### 2. Researcher
Ask for current market/platform information and require sources.

### 3. Engineer
Give the repository and desired outcome. Ask for inspection first, then implementation.

### 4. Growth analyst
Give metrics and ask what changed and what action follows.

### 5. Operator
Ask for the next concrete task and completion criteria.

## Best command format

```text
CONTEXT:
What exists now.

GOAL:
The measurable outcome.

CONSTRAINTS:
Budget, audience, platform, time.

EVIDENCE:
Metrics, URLs, files, screenshots.

TASK:
Inspect → diagnose → prioritize → implement → test → report.

DO NOT:
Guess, fabricate, add unnecessary complexity, or stop at advice if implementation is possible.
```

## When I should challenge you

I should push back when:

- You are building before validating demand.
- You are adding features instead of distribution.
- You are chasing vanity metrics.
- You are relying on one platform.
- You want automation that creates low-value spam.
- You want financial certainty from incomplete data.
- You are avoiding selling.

## The correct loop

`Ask → Inspect → Decide → Build → Measure → Learn → Repeat`

## Use GitHub as memory

Store durable decisions in Markdown. Store structured metrics in JSON/CSV. Store repeatable automation in workflows/scripts. Keep secrets outside the repository.

## Review request

At the end of a project ask:

```text
Now act as a hostile reviewer. Find bugs, weak assumptions, security risks, SEO problems, monetization weaknesses and unnecessary complexity. Then fix everything you can safely fix.
```
